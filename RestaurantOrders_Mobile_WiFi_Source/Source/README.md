# Σύστημα Παραγγελιοληψίας

Web εφαρμογή (ASP.NET Core / Blazor Server, .NET 8) που τρέχει σαν **ένας server**
στο μαγαζί σου, και οι σερβιτόροι τη χρησιμοποιούν από **browser** σε tablet,
κινητό ή PC (χωρίς εγκατάσταση τίποτα σε αυτές τις συσκευές).

## Τι κάνει

- **Αρχική οθόνη** (`/`): 3 μεγάλα κουμπιά — **"Πάρτε παραγγελία"**, **"Επεξεργασία
  προγράμματος"**, **"Προσθήκη χρηστών"**.
  - **Πάρτε παραγγελία** → εμφανίζονται όλοι οι καταχωρημένοι χρήστες σαν καρτέλες.
    Πατάς το όνομά σου (+ κωδικό αν έχεις ορίσει) και μπαίνεις κατευθείαν στα
    τραπέζια. **Διπλό κλικ/tap** σε ένα τραπέζι για να μπεις μέσα. Εκεί ο κατάλογος
    εμφανίζεται σε **καρτέλες ανά κατηγορία** (π.χ. Καφέδες, Ποτά). Επιλέγοντας ένα
    είδος, μπορείς να πατήσεις **"Extra"** για πολλαπλά συστατικά/παραλλαγές (π.χ.
    πολύ γλυκός, μέτριος, σκέτος) και να ρυθμίσεις ποσότητα. Με **"Αποστολή στην
    κουζίνα/μπαρ"** τυπώνεται αυτόματα σε κάθε εκτυπωτή το σωστό δελτίο.
  - **Επεξεργασία προγράμματος** → εμφανίζονται **μόνο οι διαχειριστές**. Ο καθένας
    μπαίνει με τον δικό του κωδικό, και πάει στο πλήρες admin panel (τραπέζια,
    εκτυπωτές, κατηγορίες, κατάλογος, extra, χρήστες).
  - **Προσθήκη χρηστών** → πάλι μόνο διαχειριστές, login, και ανοίγει κατευθείαν μια
    σύντομη φόρμα: **Όνομα** (υποχρεωτικό), Επώνυμο, Κωδικός, Τηλέφωνο, Ιδιότητα
    (π.χ. Σερβιτόρος, Barman) — όλα προαιρετικά εκτός από το Όνομα.
- **Κωδικός εισόδου**: προαιρετικός ανά χρήστη. Αν δεν οριστεί, ο χρήστης μπαίνει
  πατώντας απλά την καρτέλα του, χωρίς να του ζητηθεί τίποτα.
- **Πλήρης διαχείριση χρηστών** (`/admin/users`, μέσα από το admin panel): εκεί
  μπορείς να φτιάξεις και άλλους λογαριασμούς **Διαχειριστή**, να ενεργοποιήσεις/
  απενεργοποιήσεις χρήστες, να αλλάξεις κωδικό, ή να διαγράψεις.

## Απαιτούμενα

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) στον υπολογιστή
  που θα λειτουργεί σαν server.
- Οι δικτυακοί εκτυπωτές (ESC/POS, π.χ. Epson TM-T88, Star κ.λπ.) να είναι στο
  ίδιο δίκτυο (WiFi/LAN) και να ξέρεις την **IP διεύθυνσή** τους. Θύρα συνήθως 9100.

## Πρώτη εκκίνηση

⚠️ **Αν έτρεχες ήδη παλιότερη έκδοση**, σβήσε πρώτα το αρχείο `restaurant.db`
(και `restaurant.db-shm` / `restaurant.db-wal` αν υπάρχουν) μέσα στον φάκελο
`RestaurantOrders/RestaurantOrders` πριν τρέξεις ξανά — άλλαξε το μοντέλο χρήστη
και η παλιά βάση δεν έχει τις νέες στήλες. Θα ξαναφτιάξεις τα τραπέζια/κατάλογο.

```bash
cd RestaurantOrders
dotnet restore
dotnet run
```

Η εφαρμογή θα ακούει στο `http://<IP-του-υπολογιστή>:5000` (βλ. `appsettings.json`
για αλλαγή θύρας/διεύθυνσης). Οι συσκευές σερβιτόρων ανοίγουν αυτή τη διεύθυνση
από τον browser τους (π.χ. `http://192.168.1.10:5000`) — βάλε το ως σελιδοδείκτη /
συντόμευση στην αρχική οθόνη του tablet.

Στην πρώτη εκκίνηση δημιουργείται αυτόματα ο πρώτος λογαριασμός διαχειριστή:

- **Όνομα:** Διαχειριστής / **Κωδικός:** `1234` (καρτέλα στο "Επεξεργασία προγράμματος")

⚠️ **Άλλαξέ τον αμέσως** από τη σελίδα "Χρήστες": φτιάξε νέο admin με δικό σου
κωδικό, μετά σβήσε ή απενεργοποίησε τον default admin.

## Ρύθμιση από το admin panel

Σειρά που προτείνεται:

1. **Εκτυπωτές** (`/admin/printers`): πρόσθεσε κάθε φυσικό εκτυπωτή με όνομα +
   IP + θύρα. Χρησιμοποίησε "Δοκιμαστική εκτύπωση" για να επιβεβαιώσεις σύνδεση.
2. **Κατηγορίες** (`/admin/categories`): π.χ. "Κυρίως", "Ορεκτικά", "Ποτά",
   "Επιδόρπια" — κάθε μία συνδεδεμένη με τον εκτυπωτή που θέλεις να τυπώνει.
3. **Κατάλογος** (`/admin/menu`): πρόσθεσε τα είδη, με τιμή και κατηγορία.
4. **Extra** (`/admin/extras`): συστατικά/παραλλαγές ανά κατηγορία (π.χ. πολύ
   γλυκός/μέτριος/σκέτος για τους καφέδες).
5. **Τραπέζια** (`/admin/tables`): πρόσθεσε τα τραπέζια του μαγαζιού.
6. **Χρήστες**: είτε γρήγορα από την αρχική ("Προσθήκη χρηστών"), είτε πλήρως
   από το `/admin/users` μέσα στο admin panel.

## Ελληνικά στην εκτύπωση

Το ticket στέλνεται με ελληνική codepage (Windows-1253 / ESC t 11, συνηθισμένη
για Epson TM σειρά). Αν ο δικός σου εκτυπωτής δείχνει περίεργους χαρακτήρες αντί
για ελληνικά, άνοιξε το `Services/PrinterService.cs` και άλλαξε την τιμή στη
γραμμή:

```csharp
private static readonly byte[] SelectGreekCodepage = { 0x1B, 0x74, 11 };
```

Δοκίμασε 7 ή άλλες τιμές ανάλογα με το manual του μοντέλου σου.

## Βάση δεδομένων

SQLite, ένα αρχείο (`restaurant.db`) δίπλα στο εκτελέσιμο — δημιουργείται αυτόματα.
Backup = απλά αντιγραφή αυτού του αρχείου.

⚠️ Αν αλλάξεις τα models (π.χ. προσθέσεις πεδίο), σβήσε το `restaurant.db` για να
ξαναδημιουργηθεί το σχήμα (δεν υπάρχουν scaffolded EF migrations — έγινε
`EnsureCreated()` για απλότητα).

## Μαζικές ενέργειες στον κατάλογο

- **Μαζική προσθήκη ειδών** (`/admin/menu`): γράφεις ένα είδος ανά γραμμή
  (προαιρετικά `Όνομα;Τιμή`), διαλέγεις προαιρετικά μία κατηγορία για όλη τη
  λίστα, και προστίθενται όλα μαζί.
- **Μαζική ανάθεση κατηγορίας**: επίλεξε πολλά είδη (checkboxes / "Επιλογή
  όλων") και ανάθεσέ τους κατηγορία με ένα κλικ.
- **Μαζική ανάθεση εκτυπωτή σε κατηγορίες** (`/admin/categories`): το ίδιο,
  αλλά για να βάλεις πολλές κατηγορίες σε έναν εκτυπωτή μονομιάς.
- Ούτε η **κατηγορία** σε ένα είδος, ούτε ο **εκτυπωτής** σε μια κατηγορία
  είναι υποχρεωτικά — μπορείς να τα προσθέσεις πρώτα όλα και να τα οργανώσεις
  μετά. Είδη χωρίς κατηγορία, ή κατηγορίες χωρίς εκτυπωτή, απλά δεν
  εμφανίζονται στον κατάλογο του σερβιτόρου / δεν στέλνονται πουθενά μέχρι να
  τα ρυθμίσεις.

## Επεξεργασία καταλόγου & τραπεζιών

- **Επεξεργασία είδους** (`/admin/menu`): πάτα "Επεξεργασία" σε οποιοδήποτε
  είδος για να αλλάξεις όνομα, τιμή ή κατηγορία επιτόπου.
- **Περιοχές τραπεζιών** (`/admin/tables`): φτιάξε όσες "καρτέλες περιοχής"
  θες (π.χ. "Σάλα", "Πλατεία") — εμφανίζονται σαν tabs στην οθόνη επιλογής
  τραπεζιού του σερβιτόρου, μαζί με ένα προεπιλεγμένο "Όλα τα τραπέζια".
- **Αναδιάταξη τραπεζιών**: στο admin panel, σύρε (drag & drop) τις κάρτες
  τραπεζιών για να αλλάξεις τη σειρά εμφάνισής τους — μόνο ο διαχειριστής
  έχει αυτό το δικαίωμα.
- **Ποσό ανά τραπέζι**: στην οθόνη επιλογής τραπεζιού, κάθε τραπέζι δείχνει το
  τρέχον άθροισμα της ανοιχτής παραγγελίας του (ή "Ελεύθερο" αν δεν έχει
  τίποτα), πριν καν μπεις μέσα.

## Εκτυπωτές: αντίγραφα & ήχος

- Στη σελίδα **Εκτυπωτές** (`/admin/printers`) μπορείς να ορίσεις πόσα
  **αντίγραφα** να τυπώνει ο κάθε εκτυπωτής (π.χ. 2 για διπλότυπο).
- Όταν ο σερβιτόρος στέλνει επιτυχώς παραγγελία σε κάποιον εκτυπωτή, η
  συσκευή του παίζει ένα σύντομο **"ding"** για επιβεβαίωση (δεν χρειάζεται
  ηχείο στον ίδιο τον εκτυπωτή).
- Γραμματοσειρά/μέγεθος/λογότυπο ανά εκτυπωτή: υπάρχει ήδη η υποδομή στο
  `Services/PrinterService.cs` — πες μου συγκεκριμένα τι θες και το προσθέτω.

## Ελεύθερη Κάτοψη (Floor Plan)

- Στο **Κάτοψη** (`/admin/floorplan`): πάτα ένα τραπέζι από τη λίστα (φωτίζεται), μετά πάτα
  πάνω στην κάτοψη εκεί που θέλεις να το τοποθετήσεις — ελεύθερα, όπου θες. Για να το
  μετακινήσεις, πάτα το ξανά και μετά πάτα τη νέα θέση. Δουλεύει το ίδιο με ποντίκι ή με
  δάχτυλο σε tablet.
- Ο σερβιτόρος βλέπει την ίδια κάτοψη στην οθόνη επιλογής τραπεζιού (`/waiter`), με το ποσό
  της παραγγελίας κάτω από κάθε τραπέζι. Τραπέζια που δεν έχουν τοποθετηθεί ακόμα στην
  κάτοψη εμφανίζονται σε μια απλή λίστα από κάτω.

## Μαζική εισαγωγή από Excel

- **Κατάλογος** (`/admin/menu`) και **Extra** (`/admin/extras`): ανέβασε ένα αρχείο
  `.xlsx` με επικεφαλίδες στην πρώτη γραμμή:
  - Κατάλογος: **Περιγραφή**, **Κατηγορία**, **Τιμή**
  - Extra: **Extra**, **Κατηγορία** (προαιρετικό — κενό σημαίνει "όλες οι κατηγορίες")
  - Η σειρά των στηλών δεν έχει σημασία. Κατηγορίες που δεν υπάρχουν ήδη δημιουργούνται
    αυτόματα.

## Αποστολή παραγγελίας χωρίς εκτυπωτή

Η αποστολή της παραγγελίας (κουμπί "Αποστολή στην κουζίνα/μπαρ") πλέον **πάντα**
καταχωρεί την παραγγελία κανονικά, ό,τι κι αν γίνει με την εκτύπωση: αν μια κατηγορία δεν
έχει ακόμα εκτυπωτή, ή αν αποτύχει η σύνδεση με κάποιον εκτυπωτή, τα είδη καταχωρούνται
σαν σταλμένα ούτως ή άλλως — η εκτύπωση είναι απλά "καλύτερα να γίνει" (best-effort), δεν
μπλοκάρει ποτέ τον σερβιτόρο.

## Extra: ίδια λογική με τον κατάλογο

Στη σελίδα **Extra** (`/admin/extras`) τώρα έχεις ό,τι και στα είδη του καταλόγου:
- Προσθήκη ενός extra (με προαιρετική τιμή)
- Μαζική προσθήκη πολλών (ένα ανά γραμμή)
- Εισαγωγή από Excel
- Μαζική επιλογή + ανάθεση κατηγορίας
- Επεξεργασία (όνομα, τιμή, κατηγορία) ανά πάσα στιγμή

Αν ένα extra έχει τιμή (π.χ. "Με κρέμα" +€0.50), αυτή προστίθεται αυτόματα στο σύνολο
της παραγγελίας όταν ο σερβιτόρος το επιλέξει.

## Κάτοψη: πραγματικό σύρσιμο

Στην Κάτοψη (`/admin/floorplan`), πιάνεις ένα τραπέζι (από τη λίστα ή πάνω στην κάτοψη) και
το σύρεις κρατώντας πατημένο το ποντίκι — ακολουθεί τον κέρσορα, αφήνεις όπου θες.
Λειτουργεί καλύτερα από υπολογιστή (το native browser drag δεν δουλεύει το ίδιο καλά σε
tablet/κινητό με το δάχτυλο).

## Αναφορές Πωλήσεων

Στη σελίδα **Αναφορές** (`/admin/reports`):
- Διαλέγεις διάστημα ημερομηνιών (Από / Έως — μπορεί να είναι και η ίδια μέρα).
- Βλέπεις τις πωλήσεις **ομαδοποιημένες ανά κατηγορία και είδος**, με ποσότητα και έσοδα
  (μετράει μόνο είδη που έχουν πράγματι σταλεί/επιβεβαιωθεί στην κουζίνα/μπαρ).
- Πατώντας **"Εξαγωγή σε Excel"** κατεβάζεις ένα `.xlsx` με την ίδια ανάλυση
  (Κατηγορία, Είδος, Ποσότητα, Έσοδα, και σύνολα).

## Τρέξιμο ως Windows Service

Η εφαρμογή είναι πλέον έτοιμη να τρέχει σαν Windows Service (χωρίς ανοιχτό παράθυρο
κονσόλας, ξεκινάει αυτόματα με τα Windows). Βήματα:

1. **Δημοσίευση (publish) του project** σε φάκελο:
   ```bash
   dotnet publish -c Release -r win-x64 --self-contained true -o C:\RestaurantOrdersApp
   ```
   (το `--self-contained true` σημαίνει ότι δεν χρειάζεται να έχει εγκατεστημένο .NET
   ο υπολογιστής-server — μεγαλύτερο μέγεθος, αλλά πιο απλό στη μεταφορά).

2. **Δημιουργία της υπηρεσίας** (άνοιξε Command Prompt/PowerShell **ως Administrator**):
   ```powershell
   sc create RestaurantOrdersService binPath= "C:\RestaurantOrdersApp\RestaurantOrders.exe" start= auto
   sc description RestaurantOrdersService "Σύστημα Παραγγελιοληψίας"
   sc start RestaurantOrdersService
   ```
   ⚠️ Πρόσεξε τα κενά μετά τα `binPath=` και `start=` — τα θέλει το `sc.exe` έτσι.

3. Η εφαρμογή θα τρέχει πλέον μόνιμα στο παρασκήνιο, θα ξεκινάει αυτόματα με τα Windows,
   και θα είναι προσβάσιμη στο `http://<IP-του-υπολογιστή>:5000` όπως πριν.

4. **Για να τη σταματήσεις/διαγράψεις αργότερα:**
   ```powershell
   sc stop RestaurantOrdersService
   sc delete RestaurantOrdersService
   ```

Αν προτιμάς πιο εύκολο εργαλείο αντί για `sc.exe`, το [NSSM](https://nssm.cc/) κάνει το ίδιο
πράγμα με γραφικό interface.

## Δελτίο εκτύπωσης: νέα διάταξη, codepage, "Λογαριασμός"

- **Νέα διάταξη δελτίου**: το όνομα τραπεζιού είναι τώρα πάνω-πάνω (μεγάλο/έντονο), από
  κάτω το όνομα του σερβιτόρου δεξιά στοιχισμένο, μετά κάθε είδος με την τιμή του δίπλα.
- **Λάθος ελληνικά στην εκτύπωση;** Στη σελίδα **Εκτυπωτές** (`/admin/printers`) άλλαξε
  το **Codepage** του συγκεκριμένου εκτυπωτή (PC737 ↔ Windows-1253) και ξανακάνε
  "Δοκιμαστική εκτύπωση" — διαφορετικά μοντέλα εκτυπωτών περιμένουν διαφορετική κωδικοποίηση.
  Υπάρχει επίσης πεδίο "Χαρακτήρες/γραμμή" (32 για στενό χαρτί 58mm, 42-48 για 80mm) ώστε
  η στοίχιση τιμών να βγαίνει σωστά ανάλογα με το πλάτος του χαρτιού σου.
- **Κουμπί "Λογαριασμός"** (δίπλα στο "Κλείσιμο τραπεζιού"): τυπώνει αναλυτικά όλα τα είδη
  του τραπεζιού με τις τιμές τους και το σύνολο κάτω-κάτω — χωρίς να κλείνει το τραπέζι.
  Τυπώνεται σε όλους τους εκτυπωτές που χρησιμοποιεί το τραπέζι (π.χ. αν έχει είδη
  από κουζίνα ΚΑΙ μπαρ, θα βγει αντίγραφο και στους δύο).
- **Αν βλέπεις "παλιά" είδη να ξανατυπώνονται μαζί με τα νέα**: το σύστημα ήδη στέλνει
  μόνο τα ΝΕΑ (μη σταλμένα) είδη σε κάθε "Αποστολή". Αν στο χαρτί φαίνονται όλα μαζί
  σαν ένα, το πιο πιθανό είναι ότι ο εκτυπωτής δεν κόβει το χαρτί ανάμεσα σε δύο
  ξεχωριστές αποστολές (δεν υποστηρίζει/αναγνωρίζει την εντολή κοπής) — οι δύο αποδείξεις
  τυπώνονται σωστά ξεχωριστές, απλά μένουν στο ίδιο συνεχόμενο χαρτί. Τώρα στέλνουμε
  πολλαπλές παραλλαγές εντολής κοπής μαζί για καλύτερη συμβατότητα με φτηνούς/clone
  εκτυπωτές — αν συνεχίζει να μην κόβει, πες μου το ακριβές μοντέλο του εκτυπωτή σου.

## Τρόπος πληρωμής & Ταμείο

- **Κλείσιμο τραπεζιού**: τώρα ρωτάει "Μετρητά" ή "Κάρτα" πριν κλείσει το τραπέζι, και το
  καταγράφει.
- **Κουμπί "Ταμείο"** (στη σελίδα `/waiter`, πάνω δεξιά): εμφανίζεται **μόνο** όταν ο
  συνδεδεμένος χρήστης είναι Διαχειριστής. Οδηγεί στο `/admin/cashier`, όπου ζητείται ξανά
  ο προσωπικός κωδικός του διαχειριστή (επιπλέον ασφάλεια πριν δει οικονομικά στοιχεία).
- **"Τρέχον Ταμείο"**: δείχνει όλες τις κλεισμένες παραγγελίες που ΔΕΝ έχουν ακόμα μπει σε
  κάποιο "Κλείσιμο Ημέρας" — μετρητά/κάρτα/σύνολο ανά υπάλληλο.
- **"Κλείσιμο Ημέρας"**: ζητάει επιβεβαίωση, μετά **παγώνει** το τρέχον ταμείο σε ένα
  μόνιμο, ξεχωριστό στιγμιότυπο (καταγράφεται πότε έγινε και ποιος το έκανε), το τυπώνει
  στον εκτυπωτή που θα διαλέξεις, και **αδειάζει** το "Τρέχον Ταμείο" — οι επόμενες
  κλεισμένες παραγγελίες μετράνε από την αρχή, μέχρι το επόμενο κλείσιμο.
- **Ιστορικό Κλεισιμάτων**: διαλέγεις ημερομηνία και βλέπεις όλα τα κλεισίματα που έγιναν
  εκείνη τη μέρα — **το καθένα ξεχωριστά** (ώρα, ποιος το έκανε, ανάλυση ανά υπάλληλο), όχι
  αθροισμένα μεταξύ τους, ακόμα κι αν έγιναν πολλά την ίδια μέρα. Κάθε κλείσιμο έχει δικό
  του κουμπί **"Λήψη PDF"**.
- **Κλείσιμο ενός μόνο υπαλλήλου**: στο "Τρέχον Ταμείο", δίπλα σε κάθε υπάλληλο υπάρχει
  κουμπί **"Κλείσιμο υπαλλήλου"** — π.χ. για κάποιον που σχόλασε νωρίτερα. Τυπώνει το δικό
  του ταμείο και αδειάζει *μόνο* τη δική του εκκρεμότητα, χωρίς να πειράζει τους
  υπόλοιπους (και χωρίς να χρειάζεται πλήρες "Κλείσιμο Ημέρας").

## Ηλεκτρονική Τιμολόγηση (Parochos / ΑΑΔΕ)

⚠️ **Πολύ σημαντικό πριν χρησιμοποιήσεις αυτό το κομμάτι σε πραγματικές συναλλαγές:**
αυτή η ενσωμάτωση στέλνει πραγματικά φορολογικά παραστατικά στην ΑΑΔΕ μέσω του Parochos.
Λάθος κωδικοί (τύπος παραστατικού, κατηγορία ΦΠΑ, τρόπος πληρωμής) μπορεί να προκαλέσουν
πραγματικό πρόβλημα με την εφορία. **Επιβεβαίωσε όλους τους κωδικούς με τον λογιστή σου
ή με τον Parochos, και δοκίμασε αποκλειστικά στο δοκιμαστικό (beta) περιβάλλον πριν
περάσεις σε παραγωγική χρήση.**

### Ρύθμιση

1. **Ρυθμίσεις Παραστατικών** (`/admin/fiscal-settings`):
   - Στοιχεία επιχείρησης (ΑΦΜ, διεύθυνση κ.λπ.)
   - Σύνδεση με Parochos: API Key (Subscription Key), Username (email), Κωδικός,
     περιβάλλον (Δοκιμαστικό/Παραγωγικό)
   - Κουμπί **"Έλεγχος σύνδεσης"** για να επιβεβαιώσεις ότι τα credentials δουλεύουν
   - Κωδικοί ΑΑΔΕ (τύπος απόδειξης/τιμολογίου, κωδικοί τρόπου πληρωμής) — έχουν λογικές
     προεπιλογές αλλά **χρειάζονται επιβεβαίωση**
2. **ΦΠΑ ανά κατηγορία** (`/admin/categories`): κάθε κατηγορία καταλόγου έχει τώρα δικό
   της συντελεστή ΦΠΑ (π.χ. Φαγητό 13%, Ποτά 24%) — σημαντικό για σωστό υπολογισμό στο
   παραστατικό.
3. **ΦΠΑ ανά είδος** (`/admin/menu`): αν κάποιο συγκεκριμένο είδος χρειάζεται διαφορετικό
   συντελεστή από την κατηγορία του, το ορίζεις εκεί — άδειο πεδίο σημαίνει "κληρονομεί
   το ΦΠΑ της κατηγορίας".

### Πώς δουλεύει στην πράξη

- Τα **δελτία παραγγελίας** (κουζίνα/μπαρ) παραμένουν όπως πριν — δεν είναι φορολογικά
  παραστατικά, απλά εσωτερική επικοινωνία.
- Στο **"Κλείσιμο τραπεζιού"**, μετά την επιλογή Μετρητά/Κάρτα, ρωτάει **Απόδειξη ή
  Τιμολόγιο**:
  - **Απόδειξη**: εκδίδεται αμέσως, χωρίς επιπλέον στοιχεία.
  - **Τιμολόγιο**: ζητάει ΑΦΜ + επωνυμία πελάτη (υποχρεωτικά) και προαιρετικά διεύθυνση.
- Το σύστημα στέλνει το παραστατικό στον Parochos, περιμένει (polling) μέχρι να
  ολοκληρωθεί η επεξεργασία από την ΑΑΔΕ, και μόνο **μετά από επιβεβαιωμένη επιτυχία**
  κλείνει το τραπέζι και "καίει" τον επόμενο αριθμό της σειράς (ώστε να μη μείνουν κενά
  στην αρίθμηση αν κάτι αποτύχει).
- Το φυσικό αντίγραφο τυπώνεται στους εκτυπωτές του τραπεζιού με τη σειρά/αριθμό και το
  ΜΑΡΚ της ΑΑΔΕ.
- Αν η αποστολή αποτύχει, το τραπέζι **ΔΕΝ κλείνει** — βλέπεις το μήνυμα σφάλματος και
  μπορείς να ξαναδοκιμάσεις.

### Τι ΔΕΝ καλύπτει ακόμα (πες μου αν τα χρειάζεσαι)

- Ενσωμάτωση με φυσικό τερματικό POS (EFT-POS) για αυτόματη υπογραφή πληρωμής καρτών —
  προς το παρόν η "Κάρτα" καταγράφεται απλά σαν τρόπος πληρωμής, χωρίς σύνδεση με το
  μηχάνημα του POS.
- Παραστατικά B2G (προς Δημόσιο).
- Λήψη/αποθήκευση του PDF από τον Parochos μέσα στην εφαρμογή (προς το παρόν το φτιάχνει
  ο Parochos αλλά δεν το κατεβάζουμε αυτόματα - μπορώ να το προσθέσω).

## Δελτίο Παραγγελίας ως ξεχωριστό φορολογικό παραστατικό (προαιρετικό)

Βάσει πραγματικού παραδείγματος απόδειξης που μας έδειξες, προστέθηκε η δυνατότητα να
εκδίδεται **και το Δελτίο Παραγγελίας** σαν δικό του φορολογικό παραστατικό στην ΑΑΔΕ
(όχι μόνο εσωτερικό χαρτάκι κουζίνας) — συνδεδεμένο μετά (`correlatedInvoices`) με την
τελική Απόδειξη/Τιμολόγιο στο κλείσιμο του τραπεζιού.

⚠️ **Απενεργοποιημένο από προεπιλογή.** Ενεργοποίησέ το από τις **Ρυθμίσεις Παραστατικών**
μόνο αφού πάρεις από τον Parochos τον σωστό κωδικό `invoiceType` για "Δελτίο Παραγγελίας"
(δεν είναι κάτι που μπορούσα να μαντέψω με σιγουριά). Όταν είναι ενεργό, κάθε "Αποστολή
στην κουζίνα/μπαρ" εκδίδει επιπλέον ένα Δελτίο Παραγγελίας — αν αυτό αποτύχει, το
δελτίο πηγαίνει κανονικά στην κουζίνα (δεν μπλοκάρεται η λειτουργία), αλλά βλέπεις
προειδοποίηση στην οθόνη.

## Διόρθωση: πολλαπλή κοπή χαρτιού

Παλιότερα στέλναμε 3 διαφορετικές εντολές κοπής μαζί "για συμβατότητα" με διάφορα μοντέλα
εκτυπωτών. Αν ο εκτυπωτής σου αναγνωρίζει και τις τρεις, έκοβε 3 φορές στη σειρά. Τώρα
στέλνεται μόνο η βασική, τυπική εντολή πλήρους κοπής (GS V 0).

## Διορθώσεις εκτύπωσης (€, ΦΠΑ, "σπασμένη" γραμμή συνόλου)

- **Σωστό σύμβολο "€"**: το παλιό ελληνικό codepage (PC737) δεν έχει καθόλου το σύμβολο
  ευρώ, γι' αυτό έβγαζε "?". Τώρα το "€" γράφεται πάντα σωστά (μέσω στιγμιαίας εναλλαγής
  σε Windows-1253 μόνο για αυτόν τον χαρακτήρα), ανεξάρτητα από ποιο codepage έχεις
  επιλέξει για τα ελληνικά.
- **Στήλη ΦΠΑ**: κάθε είδος στο δελτίο/λογαριασμό δείχνει τώρα και το ποσοστό ΦΠΑ του,
  δίπλα στην περιγραφή.
- **Το "0" κάτω από το ΣΥΝΟΛΟ**: έφταιγε η "διπλή γραμματοσειρά" (διπλό πλάτος) που
  χρησιμοποιούσα σε αυτή τη γραμμή — έκανε τη γραμμή να μην χωράει στο πλάτος του χαρτιού
  και το τελευταίο ψηφίο "έσπαγε" σε ξεχωριστή γραμμή. Αφαιρέθηκε το διπλό μέγεθος από
  αυτή τη γραμμή (έμεινε μόνο έντονη γραφή) και το πρόβλημα λύθηκε.

## Parochos API v3 integration

Η ενσωμάτωση του Parochos έχει προσαρμοστεί στην τεκμηρίωση API v3.0.29:

- Login μέσω `loginToSubscription` και δυναμικό `url1`.
- JWT + refresh token με cache στη μνήμη.
- `X-Version: 3.0` σε όλες τις Provider API κλήσεις.
- `api/send` χρησιμοποιεί `identifier = "Parochos"`.
- Polling μέσω `api/get` μέχρι να ολοκληρωθεί η έκδοση.
- Απόδειξη / Τιμολόγιο με αποθήκευση MARK, UID, authentication code, QR και PDF URL.
- Order Forms με `invoiceType = 8.6`, Point of Service, AssignDocument και ConnectDocuments.
- EFT-POS flow με `requestPayment` και payment signature.

### Κάρτα / EFT-POS

Το Parochos API δημιουργεί το provider payment signature, αλλά η πραγματική συναλλαγή
στο POS terminal εξακολουθεί να γίνεται από το EFT-POS / τον αντίστοιχο NSP μηχανισμό.
Η εφαρμογή ζητά το Transaction ID που επέστρεψε το POS και μετά το στέλνει στο Parochos
μαζί με signature, terminalId και nspCode.

Το Parochos HTTP API από μόνο του δεν πατάει το POS. Για αυτόματη συναλλαγή χρειάζεται
connector του συγκεκριμένου EFT-POS/NSP. Το project περιλαμβάνει ePay WebECR και EDPS
Middleware Chronos WebECR API v6 connectors· οι υπόλοιπες συνδέσεις εξακολουθούν να χρειάζονται το
δικό τους πρωτόκολλο ή SDK.

Για EDPS Middleware ρυθμίσεις, redeem, identifiers και UAT/production περιβάλλον, δες το
`EDPS_WEBECR_SETUP_EL.md`.

### Ρυθμίσεις

Στο `/admin/fiscal-settings` συμπληρώνονται:

- Subscription Key
- API User / API Password
- Beta ή Production
- Transmission Type (`1` για PDF ή `5` χωρίς PDF)
- EFT-POS Terminal ID
- EFT-POS NSP Code
- Special Invoice Category (default `12` για restaurant/catering requestPayment)
- Receipt / Invoice types
- Order Form type (`8.6`)

Το `restaurant.db` διατηρείται όταν προστίθενται τα νέα πεδία: κατά την εκκίνηση γίνεται
έλεγχος του SQLite schema και προστίθενται μόνο οι ελλείπουσες στήλες.


## Υποστήριξη κινητών Android και iOS μέσω Wi-Fi

Η εφαρμογή μπορεί να ανοίγει από Chrome σε Android και Safari σε iPhone όταν το κινητό και ο Windows υπολογιστής βρίσκονται στο ίδιο έμπιστο Wi-Fi. Το build release ορίζει Kestrel στο `http://0.0.0.0:5000`, ενώ το installer ανοίγει TCP 5000 μόνο σε Private προφίλ και LocalSubnet. Από το κινητό ανοίγεις `http://IP-ΤΟΥ-SERVER:5000` (η πραγματική IPv4 φαίνεται στην εντολή `ipconfig`). Η βάση και οι εκτυπωτές μένουν στον server. Μην κάνεις port forwarding. Δες το `MOBILE-WIFI-GUIDE-EL.txt` στο build kit για πλήρεις οδηγίες.
